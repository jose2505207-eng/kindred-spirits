# Working in this repo

Read `docs/ALGORITHM.md` and `docs/DESIGN.md` before touching anything. They
carry context that took real effort to recover and is not obvious from the
code.

## The engine is load-bearing

`engine/kindredEngine.js` is the reading engine. `engine/kindred_spirits.py` is
the reference implementation the JS is checked against. They must stay in
agreement.

Rules:

- **Never change a number in the engine to make a UI problem go away.** The
  card tables, offsets and rounding were validated against the disclosure's own
  Appendix B chart. If a reading looks wrong, the UI is wrong first.
- Run `npm test` after any change that touches `engine/`. All 10 tests must
  pass. If you change the Python reference, regenerate the parity fixture.
- Every data table in the engine carries a provenance tag (`[DOC]`, `[FIG]`,
  `[DERIVED]`, `[ASSUMED]`). Preserve them. Add one if you add a table.
- The engine imports nothing. Keep it that way — it is meant to move to React
  Native untouched.

## Scope

The app has a real backend: Supabase Postgres, Auth, Storage and Realtime
(project `ofmlahcfcuhwykgzupey`) behind the React/Vite PWA. This replaces the
earlier prototype rule of no auth, no database and no backend calls.

- **The database stores people, not readings.** Birthdates and profile data
  live in Postgres. Readings and rankings come from `engine/kindredEngine.js`
  only. Never reimplement any part of the reading, the card tables, the offsets
  or the tier ladder in SQL, an RPC, a trigger, or a cache the UI trusts.
- **The repo is the source of truth for the schema.** One migration per concern
  in `supabase/migrations/`; anything applied to the project is committed
  there. The `*_cards.sql` migration is generated by
  `scripts/generate-cards-migration.mjs` from the engine — rerun it, never edit
  it by hand.
- **RLS on every table**, with explicit policies and nothing granted to `anon`
  that it does not need. Helpers that policies and triggers call live in the
  unexposed `private` schema.
- Messages go through `src/lib/messaging.js`; nothing else may know where
  messages live.
- Seeded fixture profiles stay available behind `VITE_DEMO_MODE`, so the client
  review build still runs with no accounts.
- Where each person's birth year is visible, and the server-side alternative, is
  recorded in `docs/DESIGN.md` under "Who can see a birth year".

`@supabase/supabase-js` is the only backend dependency. Do not add a state
management library, a component library, or a test framework beyond
`node:test`. If a dependency feels necessary, say why before adding it.

## Confidentiality

This implements a confidential third-party patent disclosure. Keep the repo
private. Do not publish the algorithm, the derivations, or the card tables
anywhere public, and add `noindex` to any deployed build. That includes the
backend: no card tables, derivations or engine logic in migrations, Edge
Functions, seed files, or any public Storage object. The `cards` table holds
card names and art paths only, never the engine's deck order or indices.

## Style

Match the existing prototype: plain CSS in a `<style>` block with custom
properties, no utility-class framework. Sentence case, no ALL-CAPS labels.
Copy should sound like the disclosure's own Output Examples — "a natural fit",
"marginally compatible" — not like generic app copy.

Keep commits small and describe what changed and why.
